# ETP-4752 — Select Pre-Push Playwright Coverage from the Diff

Jira: https://etendoproject.atlassian.net/browse/ETP-4752

## Goal

Reduce pre-push cost by preparing and running Playwright only when the changed
files require browser-level validation, without relying on an interactive
`y/N` decision.

## Classification

- `no-e2e`: docs, dependencies, locales, unit tests and internal changes without
  observable interaction.
- `e2e-mocked`: navigation, forms, modals, visibility and UI serialization.
- `e2e-integration`: real persistence, NEO endpoints, defaults and backend rules.
- `e2e-full`: E2E infrastructure or high-impact transversal changes.

## Acceptance Criteria

- Diff-aware classification is the default pre-push behavior.
- Pre-push output prominently reports the analyzed diff, changed-file count,
  test profile, E2E classification, Playwright action, required environment and
  classification reasons before executing the plan.
- The current interactive Playwright `y/N` prompt is removed.
- `no-e2e` does not prepare a Playwright environment.
- `e2e-mocked` runs the mocked Playwright project and starts the mock server when
  it is not already reachable.
- `e2e-integration` runs the integration project against a reachable environment.
- `e2e-full` runs every Playwright project against a prepared environment.
- Missing required environments block the push with actionable instructions.
- Unknown or broad changes select the conservative full fallback.
- Target-branch synchronization merges keep normal final-diff classification;
  merges from another feature or an unproven parent select `e2e-full`.
- Automated tests cover all classification levels.
- Historical validation treats only reproducible, causally related failures as
  selector false negatives; flaky or unrelated failures are reviewed separately.

## Initial Evidence

The latest 100 merged PRs classified as 22 `no-e2e`, 30 `e2e-mocked`, 30
`e2e-integration` and 18 `e2e-full`. Retained Jenkins history covered 17 PRs;
11 reached Playwright. One raw `no-e2e` failure candidate was dismissed because
the failing flows were unrelated to the translation-only diff and Playwright
reported a flaky outcome. This is zero confirmed false negatives, but not yet a
conclusive sample.
