# Balance Sheet

## Intent
Give finance users a point-in-time snapshot of assets, liabilities, and owner equity grouped by accounting category, sourced from `fact_acct` and the chart of accounts, so they can review the company's financial position for a chosen accounting schema, organization, and year (old viewer) or, with the `dynamic-balance-reports` flag (shared with the Trial Balance; Profit & Loss stays on `dynamic-reports`), at any date with live filters, comparisons and a ledger drill-down.

## What this report should allow
- Browse the report from the Finance / Reports menu listed as **Balance de Situación** (es) / **Balance Sheet** (en).
- Pick an Accounting Schema (General Ledger), an Organization, and a Year before running.
- Render the report inline as HTML preview and download it as PDF, XLSX, or CSV.
- XLSX and CSV are a flat grid with the columns **Grupo · Profundidad · Tipo · Código · Nombre · Importe** (+ **Importe de Referencia** when comparing), headers translated and identical in both formats (ETP-5663). **Profundidad** is the tree indent, which varies by branch; **Tipo** is the account type from `C_ElementValue.ElementLevel` (Epígrafe / Cuenta / Desglose / Subcuenta), or **Total** on a formula heading (`A.TOTAL`, `P.TOTAL`; P&L's `P.G.A`–`P.G.D`). A formula at a lower level is a mirror account such as `(5510)` = −1 × `5510`, so it keeps its own type (Desglose). Profit & Loss exports the same columns.
- Export numeric cells (ETP-6080, ETP-6083): `template-excel.hbs` / `template-csv.hbs` / `helpers.js` are shared with Profit & Loss, whose variation columns use `numCellType` + `round2` (2 decimals; an empty cell, never `NaN`, when there is no %). Since ETP-6083 the contract declares `labels.variationAmount` / `variationPct`, so with a comparison the PDF, XLSX and CSV add **Variación** and **Variación %** after the reference amount (empty % when the reference is 0), exactly as Profit & Loss does. Without a comparison the exports are unchanged.
- Show the chart as the Classic account-report tree (`c_acct_rpt`, `reportType = 'Y'`): two bands, **Activo** and **Patrimonio Neto y Pasivo**, each with its `A)` / `B)` / `C)` groups, then epígrafes (`I.`, `II.`…), accounts and subaccounts, indented by depth, with a `TOTAL` formula row per band. The two root nodes (`A`, `P`) are never listed as rows (`buildAccountReportTree` skips roots): the bands are the group headers. The old `1. Assets / 2. Liabilities / 3. Owner Equity` grouping no longer exists.
- Signs follow the report tree: assets in debit − credit, equity and liabilities in credit − debit. The result of the year is the income-summary account (129), computed on the fly from the P&L accounts when the year is not closed (see *Result row (129)* below).
- Hide accounts whose net movement is below `0.01` (`HAVING ABS(...) > 0.01`).
- Apply organization scoping through `ad_isorgincluded` so child organizations inherit the parent's accounts.
- Honour each account's `ShowValueCond` like Classic (ETP-5662): a summary account marked `P` (positive only) or `N` (negative only) shows 0 otherwise, and so do its descendants, so PGC mirror accounts (`551` / `(551)`) show on one side only. Needs the `C_ElementValue_Operand` rows (data-fix R39); fold in `buildAccountReportTree` (`report-grouping.js`) and Java `AccountReportTree`; the SQL selects `ev.showvaluecond, ev.issummary`.
- Keep the group heading (Activo / Patrimonio Neto y Pasivo) when only one group has visible rows: a deliberate, display-only difference from Classic.
- Show the breakdown and subaccounts of a mirror account whose balance is shown (e.g. `551` with `5510` and `55100000`). Classic hides them when Compare To is off; totals are the same.

## Interaction model
- Route: `/report-viewer?report=balance-sheet`.
- No ← back button in the TopBar breadcrumb (ETP-5519, shared by every report in `ReportViewerPage.jsx`); the in-page **Cancelar** button (`action-cancel`) returns to the report catalog.
- Visibility: Finance / Reports menu, category `finance`.
- Implementation type: contract-driven SQL report served by the `report-api` Vite plugin in dev and by the static manifest in production.
- Layout: grouped listing (`type: grouped-listing`) in portrait orientation.

## Reactive behavior and dependencies
- The report does not auto-render — the user must press **Run Report** after picking parameters.
- `acctSchemaId` (General Ledger) and `yearId` (Year) are required. `orgId` is required but hidden and defaulted from the session organization.
- `yearId` depends on `orgId` via `dependsOn: "orgId"`, so the year picker filters to years valid for the active organization.
- When `yearId` is set, the SQL clamps activity to the `c_year`'s maximum `c_period.enddate`, so the report shows year-to-date balances as of year end.

### Interactive view (ETP-6083, flag `dynamic-balance-reports`)
With the flag on, `balance-sheet` is in `DYNAMIC_REPORT_IDS` and opens `components/reports/dynamic/DynamicReportView.jsx` instead of the old viewer (the engine is shared with Profit & Loss: see `docs/dynamic-reports.md`). There is no **Generar informe**: every change in **Personalizar informe** sends a new query (`POST /api/reports/balance-sheet/query`, debounced, an older request cancelled). A balance is read **at a date**, so everything below is declared in the contract and nothing in the view names the report.
- **Balance at Hasta:** the amounts are the cumulative balance up to **Hasta** (`dateTo`). The context chip reads *Balance a <fecha>*, not a period.
- **Hasta shortcuts** (`dateTo.shortcuts`): **Hoy**, **Fin del último mes**, **Fin del último trimestre** and **Fin del último ejercicio**: the end of the last *completed* month, quarter or fiscal year. The fiscal year comes from the org's `c_period` calendar (`lastCompletedYearEnd`), never an assumed 31/12; with no completed fiscal year the shortcut is disabled.
- **Desde = ledger start** (`dateFrom.role: "ledgerStart"`, shown as *Mayor desde*): it never changes the amounts. It only moves where the ledger drill starts, and it is clamped to `[start of the fiscal year of Hasta, Hasta]` (`ledgerStartFor`). The query always sends the fiscal-year start as its `dateFrom`, so editing Desde sends **no request**. Moving Hasta to another fiscal year resets Desde to that year's start. A deep link's Desde is clamped the same way once the fiscal years load, so the input never shows a date the ledger does not use. The parameter has `excludeFromSummary: true`, so the PDF/HTML filter grid does not print it (core `report-filters.js`).
- **Comparison** (`compareTo.compareModes`): **Misma fecha del año anterior** (`sameDateLastYear`) or **Cierre del ejercicio anterior** (`previousFiscalYearClose`: the last day of the fiscal year before the one that contains Hasta; without a calendar, 31/12 of last year). Each is a **one-day range** `{from: d, to: d}` (the period queries are cumulative and ignore `from`), and the panel and the *Comparado* header name the date (`Comparado (31/12/2025)`), not a range. A date with no earlier fiscal year falls back to the period-shaped comparison. Variation colours are **neutral** (no `trend` in the contract: a higher asset is neither good nor bad).
- **Fold options** (`accountLevel` options, `maxIndent`): **Grupo** (`maxIndent: 0`, the `A)` / `B)` / `C)` groups), **Epígrafe** (`maxIndent: 1`), **Cuenta** (default) and **Subcuenta**. `maxIndent` cuts by the indent of the *listed* rows (`expansionForIndent`), because roots are never rows. A **Masa** option (the two bands only) was dropped by decision: the bands and the `TOTAL` rows already are that view. `Grupo` / `Epígrafe` are `dynamicOnly` (hidden from the old viewer, `ReportViewerPage.jsx`); the old viewer's `E` (Epígrafe) and `D` (Desglose) are `legacyOnly` (hidden from the interactive view).
- **Balance check** (`"balanceCheck": true`, core): a line above the tree says the sheet balances (*Cuadra: el activo es igual al patrimonio neto y pasivo*) or prints both sides and the difference. **Partial notes:** with a Contacto or Producto filter the result is partial, so the message reads "may not balance"; with a Producto filter it adds that **opening balances carry no product**, so the balances brought forward from earlier years are missing (known limit below). The core returns `balance: null` when `showOnlyAccountsWithValue` hides a whole side.
- **Ledger drill:** an account's name or amount opens its ledger (side panel) from Desde to the cell's date with `openingEntryAmount=true`, so the **closing balance, signed like the row, equals the amount clicked** (`ledgerSummary` returns `openingSigned` / `closingSigned`). The panel prints a green *el saldo final coincide con el importe del informe*, or the difference in red (`sameAmount`, cents), unless the ledger hit its 500-line cap. A compared cell opens the ledger up to the compared date.
- **Result row (129):** the income-summary row is not a plain account. Its amount is **posted** (already regularized) plus **calculated** (the P&L accounts not yet regularized). Clicking it (name or any amount, current or compared) opens `DynamicResultPanel` instead of the ledger: *Contabilizado*, *Calculado (sin regularizar)* and the amount in the report, with a link **Abrir Pérdidas y Ganancias** (P&L from the fiscal-year start of Hasta, same org / contact / product, `RESULT_REPORT_ID = 'profit-loss'`) and **Ver el mayor de la parte contabilizada**. The calculated part is all history up to Hasta (SQL `result_onthefly*` / `own_result*`, same predicate as `sql.query`, see limits), so it **includes earlier fiscal years that were never regularized**: this is Classic's behaviour. Consequence: the panel can show more than the P&L link, which covers only the current fiscal year; the panel note says so. There is **no separate 120 row** for the earlier-years result: follow-up ETP-6405.
- **Folded levels (Grupo / Epígrafe / Cuenta):** a closed row stands for the accounts it hides (`visibleRows(..., { foldedSummary })` in `reportTree.js`). Two independent offers:
  - **Ledger:** the row opens the ledger of its hidden leaf accounts as a code range (`fromAccountId`..`toAccountId`, no `accountId`), only when the range is **contiguous**: no other leaf account of the tree has a code inside it. Charts that interleave codes across headings (e.g. Deudores comerciales takes 430-436 and 44) leave those rows plain; expand them. A ledger holds posted lines only, so when the row includes a calculated result it is compared with `amount - calculated`, and the drill panel notes the calculated part (`dynamicReportIncludesCalculated`).
  - **129 panel:** only a row made of result accounts alone (every other hidden account is zero) opens the result panel, with the on-the-fly parts added up and posted = amount - on the fly. A mixed row (Patrimonio neto) opens the ledger instead.
  - Residue: an interleaved account with a zero balance can be absent from the rows (`showOnlyAccountsWithValue`), so it cannot be detected; it adds 0 to the closing, so the check still holds.
- **Telemetry:** the usual report events (`docs/ops/app-shell-observability.md` → *Interactive report events*); opening the 129 panel emits `report_drilldown` with `type: 'result'`.
- **Exports:** PDF, XLSX and CSV render the screen's rows (`accountLevel` + `expandedNodeIds`). With a comparison they add **Variación** and **Variación %**. The PDF subtitle reads **"a <Hasta>"** (`labels.asOf`) and the comparison column names its date. `template.hbs` carries the Profit & Loss period/comparison layout port, but the Balance Sheet offers no Mes/Trimestre columns, so only the total layout is exercised today.
- **Contract keys used** (mechanics in `docs/dynamic-reports.md` and core `docs/report-query.md`): `balanceCheck`, `sql.periodQuery` / `splitQuery` / `splitPeriodQuery` (new), `dateFrom.role`, `dateTo.shortcuts`, `compareTo.compareModes`, option-level `maxIndent` / `dynamicOnly` / `legacyOnly`, `excludeFromSummary`, the `dimensiones` section (`bPartnerId`, `productId`) and the hidden `expandedNodeIds`, `splitBy`, `splitNodeId`, `splitSign`. Selections persisted in the URL: `orgId`, `dateFrom` + `dateTo`, `compare`, `bPartnerId`, `productId`.

### Known limits (ETP-6083)
- **Double count after a year close (ETP-6065).** The new queries (`periodQuery`, `splitQuery`, `splitPeriodQuery`) use the **same entry-type predicate as `sql.query`** (`factaccttype NOT IN ('R','C')`, cumulative `<= date`) on purpose (decision E1), so the interactive view and the old viewer agree to the cent. The known double count of a closed year is fixed in ETP-6065, which must change `sql.query` and the three new queries together.
- **Product filter vs opening balances:** opening entries carry no product, so with a Producto filter the balances brought forward from earlier years are missing; the balance check says so (partial note).
- **Columns by period** (Mes / Trimestre) on a balance sheet: ETP-6292.
- **Result of earlier unregularized years** has no separate row: ETP-6405.
- `sql.query` called with dates and no `yearId` returns zeros (unstripped `__YEARID__` in the CASE, the pre-ETP-6080 pattern P&L had). The dynamic view never hits it (it uses `periodQuery`) and the old viewer always sends `yearId`.
- The core's `balanceRef` (comparison balance check) is returned but not shown.
- **Pure result row without an exact range (review r5 W1, follow-up, no ticket yet):** a folded row made of result accounts alone whose code range is interleaved has no `foldedRange`, so the 129 panel's **Ver el mayor de la parte contabilizada** opens the heading's own code (an empty ledger; the closing check is green only when the posted part is 0). The panel figures are right. Narrow reach: at Cuenta, 129 is contiguous; at Grupo / Epígrafe real data has a non-zero capital or reserves, so the row is mixed and drills the ledger. The fix is to try the exact range of the result accounts only, else hide the button.
- Not verifiable locally: a **non-calendar fiscal year** (every local client starts in January); the shortcuts and `ledgerStartFor` are unit-tested only. The mixed-Grupo ledger note (a contiguous mixed row) could not be reproduced on local data either; it relies on unit/mocked tests. Verified live in the QA re-check (client asdf company): the partial note with a Producto filter, Desde clamping (deep link), the drills at Cuenta / Epígrafe, the PDF header.

## Gap assessment
- The report assumes a single accounting schema per run; consolidated multi-schema views are not exposed.
- Comparison: the old viewer compares by `referenceYearId` / reference dates; the interactive view compares one-day balances (*Interactive view* below). Columns by month/quarter are not offered on the Balance Sheet (a balance at a date has no period columns; the `columns` parameter was removed): ETP-6292.
- The English title remains "Balance Sheet" (IFRS standard); the Spanish title is the formal Spanish accounting term "Balance de Situación", not the legacy "Balance General" wording.

## Manual verification
1. Open the Reports list under Finanzas / Informes and confirm the card shows **Balance de Situación** in Spanish locale and **Balance Sheet** in English locale.
2. Click the card and confirm the report viewer header shows the same localized title.
3. Pick General Ledger and Year, leave Organization on its default, and run the report.
4. Confirm the two bands **Activo** and **Patrimonio Neto y Pasivo** appear in order, with their `A)` / `B)` / `C)` groups and a `TOTAL` row per band, and that no `A` / `P` root row is listed.
5. Confirm the result of the year (129) appears under Patrimonio Neto when income/expense activity exists, even when the year is not closed.
6. Download the report as PDF, XLSX, and CSV; confirm all three formats render the same grouping and totals.
7. In the XLSX and CSV, confirm the headers are translated and identical in both files, and the **Tipo** column reads Epígrafe / Cuenta / Desglose / Subcuenta per account and **Total** on `A.TOTAL` / `P.TOTAL` (Epígrafe until the core fold emits `isFormula`).
8. Switch organization and confirm the balance set updates accordingly (child orgs inherit via `ad_isorgincluded`).
9. Interactive view (flag on): open the report; confirm the first query runs with no button, the chip reads *Balance a <fecha>* and the check line says the sheet balances.
10. Click each **Hasta** shortcut (Hoy, Fin del último mes / trimestre / ejercicio) and confirm the date is the end of the last *completed* period of the org's calendar and the amounts change.
11. Edit **Mayor desde**: no request is sent and the amounts do not change; set it outside the fiscal year of Hasta and confirm it snaps back inside.
12. Choose **Grupo**, **Epígrafe**, **Cuenta**, **Subcuenta**: the rows fold by listed indent; there is no *Masa* option; the old viewer (flag off) offers neither Grupo nor Epígrafe-by-indent.
13. Turn on a comparison: *Misma fecha del año anterior* and *Cierre del ejercicio anterior* each name their date; variation pills are neutral.
14. Open an account ledger: the closing balance line is green and equals the clicked amount. Open the **129** row: the panel splits posted / calculated, the P&L link opens from the fiscal-year start of Hasta, and the amount may exceed the P&L when earlier years are unregularized.
15. Apply a Producto filter: the check turns into a partial note that mentions opening balances.
16. Epígrafe level: a heading whose accounts form one code range opens a ledger whose closing equals the row; one that interleaves codes (e.g. Deudores comerciales with 44) stays plain.
17. Export PDF / XLSX / CSV with and without a comparison: the PDF reads "a <Hasta>", does not print *Fecha de inicio*, and a comparison adds Variación / Variación %.
