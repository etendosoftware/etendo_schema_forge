Purchase orders: orders to vendors. Entity `header` is the order, `lines` its lines. Complete (book) one with etendo_action documentAction and parameters {"docAction":"CO"}; the documentAction field prompt lists the other values. Document tools. Several orders at once (up to 50, one result each, not atomic): etendo_action_batch (e.g. complete them all, or void drafts). Attachments: etendo_request_attachment_upload, etendo_list_attachments, etendo_delete_attachment; do not pass main:true here, the main file is the document's own PDF. PDF: etendo_get_document_pdf returns the stored PDF; a draft has none, and on no_pdf or pdf_stale the user opens the document's preview in the application. Email: etendo_send_document_email (preview:true first). Editing an order with etendo_update: a required field (for example scheduledDeliveryDate or businessPartner) cannot be cleared; sending null or an empty value for it is refused with 422 validation_error, so leave it out to keep it. A draft's currency cannot be changed to one that differs from its price list's: that update is refused with 422, so send a price list in the new currency (priceList) in the same call, or keep the currency. The order date is also the accounting date: changing orderDate updates both.
